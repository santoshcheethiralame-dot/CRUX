# Expectation–Maximization (EM)

## When do we need EM?

Sometimes the data has **latent (hidden / missing) variables** — information we'd need to estimate the model easily, but which we can't observe. This is a chicken-and-egg problem:

- if we knew the hidden labels, estimating the parameters would be easy;
- if we knew the parameters, inferring the hidden labels would be easy.

EM breaks the deadlock by **alternating** between the two.

## The two steps

> [!NOTE]
> Starting from a random parameter guess, repeat until convergence:
> - **E-step (Expectation):** using current parameters, compute the *expected* values of the hidden variables (soft assignments / posterior responsibilities) given the observed data.
> - **M-step (Maximization):** treat those expected values as if they were the true data and **re-estimate the parameters** by maximizing likelihood.

> [!INTUITION]
> E-step: "Given my current beliefs about the coins, how likely is each toss to have come from coin A vs B?" M-step: "Given those soft attributions, what bias for each coin best explains the data?" Each round improves the likelihood, climbing toward a (local) maximum.

## Worked example — two coins (Do & Batzoglou)

Two coins $A, B$ with unknown head-probabilities $\theta_A, \theta_B$. We run 5 trials of 10 flips, but **don't record which coin** was used each time — the coin identity is the latent variable.

**If we knew the coins (complete data),** estimation is trivial — just total heads / total flips: $\theta_A = 24/30 = 0.8$, $\theta_B = 9/20 = 0.45$.

**We don't, so EM.** Start with guesses $\theta_A = 0.6,\ \theta_B = 0.5$ and equal coin priors.

**E-step** — for each sequence, posterior that it was coin A (binomial likelihood):

$$P(Z_A\mid E) = \frac{P(E\mid Z_A)P(Z_A)}{P(E\mid Z_A)P(Z_A) + P(E\mid Z_B)P(Z_B)}$$

For a 5-heads/5-tails sequence this gives $P(Z_A\mid E)=0.45,\ P(Z_B\mid E)=0.55$. We then **attribute heads fractionally**: $0.45\times5 = 2.2$ heads to A, $2.8$ to B, and likewise for all 5 sequences.

| Flips | $P(A)$ | $P(B)$ | heads→A | heads→B |
|---|---|---|---|---|
| HTTTHHTHTH | 0.45 | 0.55 | 2.2 | 2.8 |
| HHHHTHHHHH | 0.80 | 0.20 | 7.2 | 1.8 |
| HTHHHHHTHH | 0.73 | 0.27 | 5.9 | 2.1 |
| HTHTTTHHTT | 0.35 | 0.65 | 1.4 | 2.6 |
| THHHTHHHTH | 0.65 | 0.35 | 4.5 | 2.5 |

**M-step** — re-estimate each bias as *expected heads ÷ expected flips attributed to that coin*:

$$\theta_A' = \frac{2.2+7.2+5.9+1.4+4.5}{10(0.45+0.80+0.73+0.35+0.65)} \approx \mathbf{0.71}, \qquad \theta_B' \approx \mathbf{0.58}$$

These become the new estimates; repeat E and M until $\theta_A, \theta_B$ stabilise (they converge toward the true 0.8 / 0.45).

## Properties

> [!TRAP]
> EM is guaranteed to **increase (never decrease) the likelihood each iteration**, but it only finds a **local** optimum — the result depends on the random initialization. In practice, **run it several times** from different starts and keep the best. It also doesn't tell you the *number* of components — that's a model-selection choice.

> [!EXAM]
> Be able to state the E-step (expected hidden variables / responsibilities) and M-step (re-estimate parameters by ML), and run one full E→M pass of the coin example: compute a posterior responsibility, attribute fractional counts, then recompute $\theta$ as weighted heads/flips. EM underpins both **GMM** and **Baum-Welch** later in this unit.
