# ESP32 & the IoT MCU Landscape

The STM32 (previous topics) is a great industrial MCU, but it needs an *external* radio to get online. The **ESP32** changed the game by putting the radio **on the chip**.

> [!NOTE]
> The **ESP32** (by Espressif) is a low-cost, low-power **system-on-chip (SoC)** with an integrated **dual-core processor**, **Wi-Fi**, and **Bluetooth/BLE** — making it a single-chip path from sensor to cloud. It's the workhorse of hobbyist and many commercial IoT products.

## Why the ESP32 dominates IoT prototyping

- **Built-in Wi-Fi + Bluetooth/BLE** — no external radio module needed; connect to the cloud out of the box.
- **Dual-core** Xtensa LX6 (typically up to 240 MHz) — one core can run networking while the other runs the app.
- **Rich peripherals** — many GPIOs, **ADC, DAC, I²C, SPI, UART, PWM**, touch-sensing, plus a low-power co-processor.
- **Very cheap** — a few dollars per dev board.
- **Huge ecosystem** — supported by **Arduino IDE, ESP-IDF (native SDK), and MicroPython**.

> [!INTUITION]
> The ESP32's superpower is **integration**: sensor → process → *and connect* on one chip. With an STM32 you'd add a separate Wi-Fi module and wire it over UART (recall Unit 2's "transmit over UART to a modem"); the ESP32 folds that radio inside, so a single cheap chip becomes a complete connected node. That's why it's the default for "make my sensor talk to the cloud" projects.

## ESP32 vs STM32 vs Raspberry Pi Pico

| | ESP32 | STM32 (F4) | Pi Pico (RP2040) |
|---|---|---|---|
| **Core** | Dual-core Xtensa LX6 ~240 MHz | ARM Cortex-M4F ~72–168 MHz | Dual-core ARM Cortex-M0+ 133 MHz |
| **Wireless** | **Wi-Fi + BLE built-in** | None (needs module) | Wi-Fi (Pico **W** only) |
| **Strength** | Connectivity, cheap, big community | Deterministic control, rich industrial peripherals (CAN, advanced timers) | Simple, cheap, great PIO |
| **Best for** | Connected IoT nodes, prototypes | Industrial/real-time control | Education, GPIO-heavy projects |

> [!TRAP]
> Don't assume "ESP32 is always best." For **hard real-time, safety-critical industrial control**, the **STM32**'s deterministic timing and peripherals (CAN, advanced timers, FPU/DSP) often win. The ESP32 shines where **wireless connectivity + low cost** matter most. Match the MCU to the job (the sensor-selection mindset, applied to processors).

## ESP32 family

Espressif has expanded the line: the original **ESP32**, the cheaper single-core **ESP32-S2** (Wi-Fi only), **ESP32-S3** (AI/ML acceleration), and **ESP32-C3** (a **RISC-V** core). The predecessor **ESP8266** was Wi-Fi-only and is still common for the simplest connected projects.

> [!EXAM]
> Know the ESP32 = low-cost SoC with **integrated Wi-Fi + Bluetooth/BLE** and a **dual-core** processor, why that makes it ideal for connected IoT, and the **ESP32 vs STM32** contrast (connectivity/cost vs deterministic industrial control). Note the ESP-IDF / Arduino / **MicroPython** toolchains.
