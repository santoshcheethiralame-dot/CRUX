# Introduction to IoT Analytics

Units 1–3 built the system that *produces* data — devices, sensors, and the networks that move readings. Unit 4 is about turning that flood of data into **value**.

> [!NOTE]
> **IoT Analytics** is the process of **collecting, processing, and analysing** the data generated by IoT devices (sensors, actuators, smart machines) to derive **actionable insights**.

Not all data is the same — and *how* you classify it decides *which* tools and methods you can use. Two classifications matter most in IoT.

## Structured vs Unstructured data

> [!NOTE]
> **Structured data** follows a defined model/schema — it fits a traditional relational database (RDBMS), often as simple **tabular** rows and columns. **Unstructured data** lacks a logical schema and doesn't fit a predefined model.

| | Structured | Unstructured |
|---|---|---|
| **Schema** | Defined (fits an RDBMS) | None |
| **Form** | Tabular (spreadsheet-like) | Free-form |
| **IoT examples** | Temperature, pressure, humidity readings in a known format | Text, speech, images, video |
| **Tools** | Wide array of standard analytics tools | Cognitive computing, machine learning |

> [!INTUITION]
> Most **sensor telemetry is structured** — a temperature value in a known field is trivial to store and query. But an estimated **~80% of business data is unstructured** (text, images, video), which is exactly why **ML and cognitive computing** get so much attention: they're the only practical way to extract meaning from data with no schema.

## Data in Motion vs Data at Rest

> [!NOTE]
> **Data in motion** is data **in transit** through the network. **Data at rest** is data **stored** — saved to a disk, storage array, or database.

- From an IoT perspective, data from smart objects is **data in motion** as it travels through the network toward its destination.
- It is often processed **at the edge** (fog computing): filtered and discarded, or forwarded for further processing/storage at a fog node or data centre.
- Once saved (hard drive, storage array, USB, database), it becomes **data at rest**.

> [!INTUITION]
> The motion-vs-rest split decides **where and how** you process. Data **in motion** suits **stream processing** at the edge — react now, drop the noise. Data **at rest** suits **batch processing** — deep historical analysis later. (This also matters for security: confidentiality must be protected for data in motion, at rest, *and* in use — a theme in the security topics.)

> [!EXAM]
> Be able to define **IoT analytics** and the two classifications: **structured vs unstructured** (schema/RDBMS-fit; ~80% of data is unstructured → needs ML) and **data in motion vs at rest** (in transit/edge-stream vs stored/batch). Know that IoT sensor telemetry is typically *structured data in motion*.
